# 0007. cwbudde fork: module path, pin policy and upstream merges

**Status:** Accepted
**Date:** 2026-09-26
**Decision-makers:** Christian Budde
**Related:** scripts/update-upstream-pin.sh, .github/workflows/upstream-pin.yml,
compat/rust-harness/Cargo.toml, go-signal PLAN.md (Phases 7–10)

## Context

[go-signal](https://github.com/cwbudde/go-signal) wants a pure-Go backend for
`go.mau.fi/mautrix-signal/pkg/libsignalgo`. Its `purego` build implements the
libsignalgo API on top of this module (in the fork `cwbudde/mautrix-signal`).
libsignalgo is generated against one exact libsignal tag (v0.102.2 for
mautrix-signal v0.2609.0), and a DB written by the CGO backend must keep working
with the pure-Go one. So this module has to be byte-compatible with **that** tag,
not with whatever upstream libsignal released last. go-signal also needs
surfaces this module lists as non-goals: zkgroup, SGX attestation and Noise for
CDSI, and HPKE.

## Decision

- **Module path** is `github.com/cwbudde/libsignal-go`. A `replace` directive
  would break `go install` for go-signal users. The rename is a single commit
  (Go imports, `go_package` options, regenerated `*.pb.go`, README, goreleaser)
  so that upstream merges conflict only where upstream touches the same lines.
- **Pin policy.** `compat/rust-harness` is pinned to the libsignal tag that
  libsignalgo expects, read from
  `cwbudde/mautrix-signal@purego:pkg/libsignalgo/signalversion/version.go`.
  `upstream-pin.yml` resolves that tag by default (a manual dispatch can still
  pass one). `compat-drift.yml` keeps reporting upstream `main` for information.
- **Re-pin procedure.** `scripts/update-upstream-pin.sh <tag>` bumps the tag
  mentions, updates the lockfile, regenerates the vectors and runs the vector,
  report and interop tests. Three things stay manual, because the script can't
  know them: `rust-toolchain.toml` must match the upstream tag's
  `rust-toolchain`, and the direct `spqr` and `libcrux-ml-kem` pins in
  `compat/rust-harness/Cargo.toml` must match what that libsignal tag pulls in
  (the workspace `Cargo.toml` of the tag). Known-answer files copied from
  upstream tests (`usernames/testdata/username_hash_vectors_v0_96_4.json`, the
  `account-keys` seed) keep their provenance tag while the upstream tests they
  came from are unchanged.
- **Upstream merges.** `upstream` = `GoCodeAlone/libsignal-go`. We **merge**
  `upstream/main` (no rebase: the fork is consumed by tag, and history must stay
  stable). After a merge: rewrite any new `GoCodeAlone/libsignal-go` imports,
  regenerate protos if a `.proto` changed, reset any harness pin change back to
  our tag, and run the full re-pin test set. Upstream re-pins to a newer tag are
  not taken over until libsignalgo moves to that tag.
- **Tags.** Fork releases are pre-releases of the next upstream patch with a
  `-cw.N` suffix (the first is `v0.7.1-cw.1`, on top of upstream v0.7.0), so
  they never collide with tags fetched from `upstream`. Consumers pin them
  explicitly.
- **Additions.** Pure-Go zkgroup (`poksho`, `zkcredential`, `zkgroup` client
  side), SGX DCAP attestation, Noise NK/NKhfs and HPKE land here as new packages
  (go-signal Phases 8–9), each with harness vectors plus live interop. They are
  offered upstream where they fit upstream's scope.

## Consequences

The harness is a contract for go-signal's pin, so a green compat run means "the
pure-Go port matches the libsignal that libsignalgo was generated against". The
fork's `upstream-pin.yml` needs the `GH_MANAGEMENT_TOKEN` secret and Actions
enabled on the fork before its scheduled runs do anything. The zkgroup,
attestation and HPKE additions widen this module beyond ADR 0006's
protocol-core scope for this fork only.

The re-pin from v0.96.4 to v0.102.2 (2026-09-26) regenerated byte-identical
vectors: upstream changes in `rust/protocol`, `rust/usernames` and
`rust/account-keys` between the two tags are dependency refactors, the removal
of `should_use_nonpq_session` (never ported here), and new account-keys APIs
(SVR2 master-key encoding, MFA metadata) that are not ported yet.
